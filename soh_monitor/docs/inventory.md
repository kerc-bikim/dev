## M-1.2 실장비 SOH 응답 채집

최소 4종을 확보한다. 저장 위치는 `backend/app/adapters/centaur_ctr/testdata/` 이며,
파일명은 아래 표의 파일명을 그대로 쓴다. 이 파일들이 Adapter 회귀 시험의 기준이 된다.

수집 명령 예:

```bash
curl -s "http://<기록계IP>/api/v1/instruments/soh?pretty=true" -o ctr4-6channel-soh.json
```

| 파일명 | 대상 | 확보 | 비고 |
|--------|------|:----:|------|
| `ctr-3channel-soh.json` | 3채널 CTR | ☐ | |
| `ctr-6channel-soh.json` | 6채널 CTR | ☐ | |
| `ctr-no-sdcard-soh.json` | SD카드 미장착 상태 | ☐ | |
| `ctr-gps-unlocked-soh.json` | GNSS 미잠금 상태 | ☐ | |
| `ctr-oldest-firmware-soh.json` | 가장 낮은 펌웨어 | ☐ | |

익명화 규칙

- 시리얼·Instrument ID 는 `centaur-6__0000` 형태로 바꾼다.
- 위도·경도는 소수점 2자리까지만 남긴다.
- 그 외 값은 **바꾸지 않는다.** 값을 다듬으면 시험의 의미가 사라진다.

## M-1.3 Mass Position 실제 경로 (중요)

공개 매뉴얼의 SOH API 채널 목록에는 `digitizer/sensor/status#_0`, `#_1` 만 있고 축별
Mass Position 값의 키는 나오지 않는다. `VM1`~`VM6` 은 Steim/SeedLink 채널 코드다.
따라서 SOH API 응답에서 축별 값이 어느 키로 오는지 실측으로 확정해야 한다.

| 항목 | 조사 결과 |
|------|-----------|
| SOH API 에 축별 Mass Position 값이 있는가 | ☐ 있다 ☐ 없다 |
| 있다면 키 형식 | |
| 단위 | |
| Sensor A 축 순서 (U/V/W 대응) | |
| Sensor B 축 순서 | |
| 없다면 대체 수집 경로 | ☐ SeedLink ☐ FDSN ☐ 기타: |

결과에 따른 처리

- API 에 있으면: `sensor.mass_position_v` 를 SOH Adapter 가 채운다.
- 없으면: 데이터 연속성 Adapter 쪽에서 채우고, SOH 쪽 capability 는 `UNSUPPORTED` 로 둔다.
