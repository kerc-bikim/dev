# ADR 0019. RESP 가져오기와 내보내기

상태: 채택  
코드: `apps/api/app/inventory/resp_convert.py`, `apps/api/app/inventory/xmlslice.py`, `apps/api/app/jobs/service.py`, `apps/web/src/editor/EditorPage.tsx`

## 맥락

M3-05는 채널 RESP와 관측소 zip을 현재 편집 StationXML에서 만들어야 한다. NRL `/combine format=resp` 를 쓰면 사용자가 고친 감도가 빠진다. PR #13 큐 구현은 이 스택의 `jobs`+`file_assets` 와 모델이 달라 가져오지 않는다.

## 결정

1. **내보내기.** `POST /api/projects/{id}/export/resp?station=&start=&nslc=` 는 공식 검증 오류가 있으면 409. 범위 XML만 잘라 `jobs.kind=resp` 로 넣는다. 워커는 StationXML → dataless(기존 M3-04) → `Parser.get_resp()`. 채널 하나면 `RESP.NET.STA.LOC.CHA`, 여러 채널이면 `{net}.{sta}.resp.zip`.
2. **감도.** InstrumentSensitivity 를 고친 값이 B058 stage 0 에 그대로 들어간다. NRL combine 을 호출하지 않는다.
3. **가져오기.** `import-file` 이 `.resp` / B050 텍스트를 받는다. ObsPy `format=RESP` 로 읽고 좌표·기간이 없으면 0·채널 시작으로 채운다. 검사 패널에 `W_RESP_INCOMPLETE` 안내. 원문 바이트는 `file_assets(kind=original)` 에 두고 편집 XML 과 덮어쓰지 않는다.
4. **권한.** 조회자는 RESP 내보내기·다운로드 403. StationXML만 받는다. 재시도는 같은 `version_id`·슬라이스 스냅샷(M3-10).

통과 시나리오: 채널 RESP, 관측소 zip, 감도 반영, RESP 가져와 좌표 수정.
