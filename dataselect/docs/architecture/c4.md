# C4 모델 — dataselect

C4는 같은 시스템을 네 단계로 확대합니다. 이 프로그램은 **단일 CLI 프로세스**이므로 컨테이너(L2)와 컴포넌트(L3)가 파일/라이브러리 경계와 거의 같습니다.

범위: 이 저장소의 `dataselect/` 트리. 입력은 시크 가능한 로컬 miniSEED 파일입니다. 파이프·stdin·URL 입력은 지원하지 않습니다.

---

## L1 — System Context

운영자 또는 배치 스크립트가 dataselect를 실행합니다. 프로그램은 여러 입력 파일을 한 덩어리로 읽고, 선택·정렬·(선택적) overlap 제거 후 출력 파일 또는 아카이브 레이아웃으로 씁니다. 입력 파일은 수정하지 않습니다.

```mermaid
C4Context
  title dataselect 시스템 컨텍스트

  Person(op, "운영자 / 배치", "선택·정렬·블록 크기 변경이 필요할 때 CLI로 실행")

  System(ds, "dataselect", "miniSEED 선택, 시간 정렬, overlap 제거, -B 재패킹")

  System_Ext(files_in, "입력 miniSEED", "v2/v3 레코드, 시크 가능한 파일. 목록 파일(@)과 바이트 범위 가능")
  System_Ext(files_out, "출력 miniSEED", "-o 단일 파일, -A/SDS 등 아카이브 트리")
  System_Ext(leap, "윤초 목록", "환경변수 LIBMSEED_LEAPSECOND_FILE")
  System_Ext(log, "로그 / 요약", "stderr 진단, -out 출력 요약")

  Rel(op, ds, "옵션과 파일 경로를 넘김")
  Rel(ds, files_in, "읽기 (CRC 검증)")
  Rel(ds, files_out, "쓰기 (입력은 변경하지 않음)")
  Rel(ds, leap, "있으면 윤초 로드")
  Rel(ds, log, "진행·오류·-out 요약")
```

**이 경계 밖:** 네트워크 수신, 실시간 링버퍼, 웹 UI. 이 바이너리는 배치 변환기입니다.

---

## L2 — Container

배포 단위는 `dataselect` 실행 파일 하나와, 링크된 `libmseed` 정적 라이브러리입니다. 선택적으로 libcurl로 libmseed URL 기능을 켤 수 있으나 **이 프로그램은 시크 가능한 파일만** 읽습니다.

```mermaid
C4Container
  title dataselect 컨테이너

  Person(op, "운영자 / 배치")

  Container_Boundary(cli, "dataselect 프로세스") {
    Container(bin, "dataselect", "C99 CLI", "선택, 가지치기, 출력, -B 훅")
    Container(lm, "libmseed", "C 라이브러리", "파싱, 트레이스 리스트, pack/unpack")
  }

  ContainerDb(fs, "파일시스템", "miniSEED 파일, SDS/BUD 디렉터리, 목록·선택 파일")

  Rel(op, bin, "argv, 종료 코드 0/1")
  Rel(bin, lm, "ms3_readtracelist_*, msr3_parse/pack, mstl3_*")
  Rel(bin, fs, "fopen/fread/fwrite, 아카이브 경로 생성")
  Rel(lm, fs, "레코드 읽기 (선택적으로 libcurl URL)")
```

테스트 컨테이너는 빌드 산출물에만 있습니다. `test/run-tests.py`가 바이너리를 실행하고, `test/compare-series`가 샘플 시계열을 비교합니다.

## L3 — Component

소스 경계는 원본에 가깝게 유지하기 위해 **세 개의 C 번역 단위 + vendored libmseed** 입니다.

```mermaid
C4Component
  title dataselect 컴포넌트 (src/)

  Component(main, "dataselect.c", "오케스트레이션", "인자, 읽기, 가지치기, writetraces, LOCAL 훅")
  Component(arch, "dsarchive.c", "아카이브", "경로 확장, 파일 그룹, idle close")
  Component(local, "local.c", "로컬 -B", "블록 크기, pack 실패 정책, v2 시퀀스, 카운트")
  Component(lm, "libmseed", "라이브러리", "MS3TraceList, 레코드 I/O, Steim 등 인코딩")

  Rel(main, lm, "트레이스 구성·unpack/pack")
  Rel(main, local, "LOCAL 훅: should_unpack, prepare_pack, stamp, note_write")
  Rel(main, arch, "ds_streamproc(msr, reclen)")
  Rel(arch, lm, "레코드 헤더로 경로 코드 확장")
```

| 컴포넌트 | 책임 | 하지 않는 일 |
|----------|------|----------------|
| `dataselect.c` | CLI, 선택/거절, overlap 가지치기, 출력 루프 | `-B` 상태와 시퀀스 맵 |
| `dsarchive.c` | `%n.%s…` 레이아웃, 열린 파일 제한 | 샘플 unpack |
| `local.c` | `-B` 파싱, 인코딩 허용, pack 실패가 fatal인지, v2 시퀀스 | 가지치기 알고리즘 |
| `libmseed` | 포맷, 연속 세그먼트, pack | 출력 정책·아카이브 레이아웃 |

원본 `dataselect.c` 변경은 `/* >>> LOCAL */` … `/* <<< LOCAL */` 훅으로만 남깁니다. 머지 절차는 [UPSTREAM.md](../../UPSTREAM.md).

## L4 — Code (쓰기 경로)

핵심 런타임 객체는 libmseed의 **레코드 리스트 인덱스**입니다. 샘플은 읽기 단계에서 풀지 않고, trim 또는 `-B`가 필요할 때만 unpack합니다.

```
MS3TraceList
  └─ MS3TraceID          (SourceID, 예: FDSN:XX_TEST__B_H_Z)
       └─ MS3TraceSeg    (연속 구간)
            └─ MS3RecordList
                 └─ MS3RecordPtr  → 파일 오프셋 + 헤더, 샘플은 아직 없음
                      └─ prvtptr: TimeRange (가지치기/선택으로 정한 새 경계)
```

쓰기 시퀀스 (`writetraces` → `trimrecord` / `writerecord`):

```mermaid
flowchart TD
  A[writetraces: ID별 레코드 리스트] --> B{local_should_unpack?}
  B -->|아니오| C[원본 바이트 writerecord]
  B -->|예| D[trimrecord: msr3_parse UNPACKDATA]
  D --> E{인코딩 pack 가능?}
  E -->|-B 이고 불가| F[종료 코드 1]
  E -->|trim 만 불가| G[원본 쓰기 + 경고]
  E -->|가능| H[샘플 trim 후 local_prepare_pack]
  H --> I[msr3_pack MSF_FLUSHDATA]
  I --> J{local_incomplete_pack?}
  J -->|예, -B| F
  J -->|예, trim 만| G
  J -->|아니오| K[writerecord]
  C --> K
  K --> L[setpubver / CRC]
  L --> M[local_stamp_v2_sequence]
  M --> N[fwrite -o]
  N --> O[필요 시 패킹된 레코드 msr3_parse]
  O --> P[ds_streamproc 아카이브]
  P --> Q[mstl3_addmsr -out]
  Q --> R[local_note_write]
```

`-B`일 때 한 입력 레코드는 여러 출력 레코드가 될 수 있습니다. 각 출력 레코드마다 `writerecord`가 호출됩니다. 입력 레코드끼리는 합치지 않습니다.

허용 pack 인코딩 (`local.c`): text, int16/32, float32/64, Steim-1/2.
