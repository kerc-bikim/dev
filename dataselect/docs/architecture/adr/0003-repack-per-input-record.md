# 0003. `-B`는 입력 레코드 단위로 다시 패킹

* 상태: Accepted
* 날짜: 2026-08
* 관련: `local_prepare_pack()`, `msr3_pack(..., MSF_FLUSHDATA)`, `trimrecord()`

## 맥락

출력 블록 크기를 512 등으로 맞추는 요구가 있습니다. 같은 채널의 연속 샘플을 모아 큰 레코드를 채우면 I/O는 줄지만, extra header·블로켓·자정 SDS 경계·Steim 재압축이 한 스트림으로 묶입니다.

## 결정

`-B`는 **기여하는 각 입력 레코드**를 unpack한 뒤 요청한 길이로 pack합니다. `MSF_FLUSHDATA`로 그 레코드의 샘플을 모두 씁니다. 입력 레코드끼리는 합치지 않습니다.

* miniSEED 2: 요청 길이로 고정(패딩).
* miniSEED 3: 요청 길이를 최대값으로 사용.
* 허용 값: 128–131072, 2의 거듭제곱.
* 샘플 시각과 값은 바꾸지 않습니다. 프레이밍만 바꿉니다.

## 결과

* 장점: 구현이 trim 경로와 같고, 시계열 비교(`compare-series`)로 검증하기 쉽습니다. 레코드별 extra header가 그 레코드의 출력에 남습니다.
* 단점: 4096→512처럼 나누면 원본 장마다 짧은 꼬리 레코드가 생깁니다. `-B 4096`으로 올려도 여러 입력을 한 장으로 모으지 않아 패딩이 늘 수 있습니다.
* 함의: “채운 뒤에만 쓰기”는 이 ADR을 뒤집는 변경입니다. 그때는 연속성·EH·SDS 자정·Steim 한도를 다시 결정해야 합니다.
